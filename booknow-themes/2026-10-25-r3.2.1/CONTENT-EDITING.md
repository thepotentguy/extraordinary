# Native content editing compatibility

The responsive R3.2.1 packages preserve the five property designs. The legacy native CMS image editor has a separate compatibility limitation: under the modern stylesheets it can show a blank cropper and required image dimensions of 0×0. Numeric dimension declarations and imported visual stylesheets did not establish a working permanent repair in the bounded diagnostic.

A comparative native test restored normal image validation with an unmodified original vendor theme uploaded to **draft only**, followed by a full switch away from and back to the property. Publication was unnecessary for the native editor to consume that draft. This supports a theme compatibility cause; the exact server parser behavior is not established.

For an authorised installer carrying out content work:

1. Preserve the current published responsive package, draft state and original content assets. Verify the intended property and editing authority.
2. Upload the original vendor theme to draft only. Do not publish the vendor appearance. Switch away and back, wait for the intended property to load, then reopen the image editor.
3. Verify the native editor reports the expected dimensions before saving. Use authentic, prepared assets: 230×100 for the site logo, 670×300 for carousel/property-gallery images and 133×99 for the property thumbnail. The native editor's actual requirement governs each collection; these collections are distinct.
4. Save the item and its containing collection/property where required. Read back the saved asset and verify unrelated fields remain unchanged.
5. Restore the property's exact frozen R3.2.1 responsive package to draft. Confirm the correct package and intended content before any separately authorised publication.
6. After publication, verify both the public responsive styles and the saved CMS assets. Check the actual gallery and location view, rather than inferring success from an upload response.

This is an editing dependency, not a permanent parser fix. Original-theme editing success does not establish general native editor compatibility with the responsive packages. The failed diagnostic packages are not final release packages. No booking, rate, inventory, payment or cancellation action is part of this workflow; existing owner access restrictions remain applicable.

Local final logo checks replayed the native 230×100 transparent logo images through the unchanged R3.2.1 styles across all five properties at 320, 390, 768, 1024, 1440 and 1920px. Thirty checks passed for natural dimensions, proportional rendering, viewport containment and absence of image filters or CSS image substitution. Ten header screenshots were reviewed for padding, background and visible brand marks. These are local fixture checks, not native CMS or full accessibility certification. No additional CSS change was required by that check.
